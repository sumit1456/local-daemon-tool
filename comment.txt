12 TOOLS THAT WORK & ARE FASTER THAN NATIVE
========================================

1. ping
   Status: Healthy on http://127.0.0.1:8000
   Use: Health check before session start

2. search_symbol
   Token cost: ~50-100
   Result: PlayerService:c:20-78 with exact line ranges
   Why better: Instant symbol lookup. Returns kind + file + line range. Grep can't do this.

3. get_overview
   Token cost: ~200-500
   Result: Compact file listing + call graph edges for a directory
   Why better: One call shows symbols and how they connect. Native requires multiple reads.

4. extract_class
   Token cost: ~100-300
   Result: Full PlayerService source (59 lines), no noise
   Why better: Read exactly one class. Native read gets entire file including imports/package.

5. extract_function
   Token cost: ~50-150
   Result: registerPlayer method body (13 lines)
   Why better: Surgical function read. Native read gets entire file.

6. get_imports
   Token cost: ~50-100
   Result: 12 imports with module path and nesting level
   Why better: One call. Native requires reading the file and parsing import lines.

7. get_callers
   Token cost: ~200-500
   Result: Found PlayerController calls registerPlayer
   Why better: Reverse call graph lookup. Native grep finds text matches, not call relationships.

8. get_callees
   Token cost: ~200-500
   Result: Found 5 callees: toEntity, saveAndFlush, publishEvent, toResponse, getDeviceId
   Why better: Forward call graph. Native requires reading source and manual tracing.

9. get_importers
   Token cost: ~200-500
   Result: Found 7 files that import Player entity
   Why better: Reverse dependency lookup across codebase. Native needs grep in every directory.

10. get_file_deps
    Token cost: ~300-600
    Result: Full bidirectional dependency graph in one call
    Why better: Replaces 2-3 separate grep calls (imports + importers).

11. get_edit_context
    Token cost: ~200-500
    Result: Source + callers + callees + imports for registerPlayer
    Why better: BEST TOOL. Replaces 4-5 native calls with one. Essential before editing any function.

12. semantic_search
    Token cost: ~200-500
    Query: "find all REST controller endpoints"
    Result: Found all 5 controllers ranked by relevance
    Why better: Natural language search. Can't do this with grep.

6 TOOLS THAT WORK BUT SLOWER/REDUNDANT THAN NATIVE
========================================

13. get_index
    Token cost: ~200-500
    Why slower: Native directory read is instant with no HTTP overhead
    When to use: Only for symbol-level overview, not simple file listing

14. get_body
    Token cost: ~200-500
    Why redundant: extract_function does the same thing cheaper (~50-150 tokens) and only needs function name
    When to use: Only if you already know exact line numbers and extract_function failed

15. get_signature
    Token cost: ~30-80
    Why unreliable: Returned empty for valid line ranges. Finicky with exact line numbers.
    When to use: Never. Use extract_function instead.

16. get_defined_symbols
    Token cost: ~50-100
    Why limited: Only works on indexed language (Java). Returned empty for Python files.
    When to use: Only for Java codebases. Use native grep for other languages.

17. impact_analysis
    Token cost: ~500-1000
    Why slower: Works but expensive. get_callers + count_references gives same info cheaper.
    When to use: Only for critical refactoring where you need the full picture.

18. reindex
    Token cost: N/A
    Why limited: One-time setup tool. Not useful during normal coding sessions.
    When to use: Only when switching repos.

# SQLite Vector Search Upgrade Plan
# CodeSearchEngine - Semantic Search Capability

## Overview
Add sqlite-vec extension for semantic code search using vector embeddings.

## Current State
- Database: aiosqlite at data/index.db
- Schema: files, symbols, edits, call_edges, symbol_references, docstrings, imports, type_hints, class_bases
- No vector search capability

## Target State
- SQLite with sqlite-vec extension
- Vector embeddings for all symbols
- Natural language code search
- Similar function discovery

---

## Implementation Steps

### Step 1: Dependencies
Add to requirements.txt:
```
sqlite-vec>=0.1.7
fastembed>=0.3.0
```

### Step 2: Schema Changes
Add to schema.sql:
```sql
CREATE TABLE IF NOT EXISTS embeddings (
    symbol_id   INTEGER PRIMARY KEY REFERENCES symbols(id) ON DELETE CASCADE,
    embedding   BLOB NOT NULL,  -- float32 vector (384 dims)
    model       TEXT NOT NULL DEFAULT 'all-MiniLM-L6-v2',
    created_at  REAL NOT NULL
);
```

### Step 3: Embedding Generation
- Use fastembed with all-MiniLM-L6-v2 model (384 dimensions)
- Generate during /reindex (background, incremental)
- Only index new/changed symbols

### Step 4: New MCP Tools

#### semantic_search(query, limit=10)
- Encode query → vector (~10ms local)
- SQL KNN query with vec_distance_cosine
- Return top-k results
- Token cost: ~200-500

#### find_similar_functions(symbol_name, limit=5)
- Get embedding for target symbol
- Find nearest neighbors
- Return similar functions
- Token cost: ~150-300

#### index_embeddings(file=None)
- Generate embeddings for symbols
- Incremental (skip already indexed)
- Token cost: ~100-200

### Step 5: API Endpoints
Add to codeengine/api/search.py:
- GET /search/semantic?q=...&limit=10
- GET /search/similar?symbol=...&limit=5

## Architecture

```
Agent → semantic_search("find auth functions")
         ↓
    fastembed encode query (~10ms)
         ↓
    SQL: SELECT ... ORDER BY vec_distance_cosine
         ↓
    Return ranked results
```

## Query Examples

### Semantic Search
```sql
SELECT s.name, s.kind, f.path, 
       vec_distance_cosine(e.embedding, :query_vec) as distance
FROM embeddings e
JOIN symbols s ON e.symbol_id = s.id
JOIN files f ON s.file_id = f.id
ORDER BY distance
LIMIT 10;
```

### Similar Functions
```sql
SELECT s2.name, f2.path, 
       vec_distance_cosine(e2.embedding, e1.embedding) as distance
FROM embeddings e1
JOIN symbols s1 ON e1.symbol_id = s1.id
JOIN embeddings e2 ON e2.symbol_id != s1.id
JOIN symbols s2 ON e2.symbol_id = s2.id
JOIN files f2 ON s2.file_id = f2.id
WHERE s1.name = 'process_payment'
ORDER BY distance
LIMIT 5;
```

## Decisions Made
1. Embedding model: fastembed (local, free, no API)
2. Indexing: LAZY - only on explicit user request (not at startup)
3. Language: Multi-language support (future-proof)
4. Embed content: Name + docstring + first 5 lines of code

## Lazy Loading Strategy
- Model NOT loaded at startup
- Toggle in UI to enable/disable embeddings
- When toggled ON: start embedding generation in background
- When toggled OFF: stop embedding
- Status shows progress (e.g., "Embedding: 45/133 symbols")
- `semantic_search` only works after embeddings are generated

## What Gets Embedded
For each function/class/method:
1. **Name**: `function authenticateUser`
2. **Docstring**: Extracted from source (if exists)
3. **First 5 lines**: Of the function body

Example embedding input:
```
function authenticateUser Validates user credentials against database and returns JWT token. async function authenticateUser(email, password) { const user = await db.findUser(email);
```

## Language Support
| Language | Docstring Pattern | Example |
|----------|------------------|---------|
| Python | `"""..."""` or `'''...'''` | `"""Login user"""` |
| JavaScript | `/**...*/` or `/*...*/` | `/** @param {string} email */` |
| TypeScript | `/**...*/` or `/*...*/` | `/** Authenticate user */` |
| Java | `/**...*/` (Javadoc) | `/** Validates credentials */` |
| Go | `/*...*/` or `//...` | `// Authenticate validates user` |
| Rust | `///...` or `//!...` | `/// Authenticate the user` |
